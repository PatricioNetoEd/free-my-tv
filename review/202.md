## Pendências obrigatórias

1. **`app/assets/i18n/vi.json:20`**: `"Appearance": "Giao diện"` é a mesma palavra de `"Theme": "Giao diện"`
   (`vi.json:288`). Em vietnamita, Home Settings mostra duas linhas seguidas com o mesmo nome. Troque *Appearance* por
   um termo diferente (por exemplo "Phong cách" ou "Kiểu hiển thị") e mantenha *Theme* como está. É a única colisão:
   nos outros 25 catálogos, *Appearance* e *Theme* são palavras diferentes.
2. **`app/src/io/freemytv/HomeView.java:2223`, `:2226` e `:2230`**: `drawerLabel.setTextSize(23 * k * s)`, o encolhimento
   até `18 * k * s` e a volta para `23 * k` desfazem, em cada quadro, o `lay.text(23)` de `makePaints` (`:962`). Por
   isso, na Nova, os rótulos das teclas da gaveta (Entradas, Atalhos) ficam com 23 px, e um nome longo encolhe até
   18 px. Isso quebra a regra `rules.min_text_px_1080p` = 24 e o critério 3 do card. O web já passa esses rótulos para
   24 px (`web/home.css:628`), então as duas plataformas ficam diferentes. Use `lay.text(23)` nas três linhas e um piso
   de `lay.text(18)`. Na Nova, o melhor é cortar com reticências em vez de encolher abaixo de 24, como o web faz. A
   Clássica não muda (`minText` = 0). Não é alocação: `setTextSize` não cria objetos.

### Bitmaps reciclados: nenhuma referência Java sobra

Toda liberação esvazia o único lugar Java que guardava o bitmap. Um desenho depois disso faz o bitmap de novo, sem usar
o reciclado.

- **Logos** (`HomeView.java:1684-1691`, `:2048-2062`): `crispLogo` só é chamado em `drawLogo` (`:2033`), que desenha na
  hora e não guarda o bitmap. Só entram em `crispMade` as cópias de `Ui.downscale`. Quando `out == src`, o logo é o de
  `HomeApps`, e o código não recicla. `Ui.downscale` (`Ui.java:389-407`) devolve `src` ou um bitmap novo, nunca um
  compartilhado. Nenhuma outra classe atribui `it.logo` a partir da HomeView (`HomeApps.java:207-210`).
- **Shadows** (`Shadows.java:74-79`, `:104`): há uma instância por HomeView (`HomeView.java:353`), usada só no UI
  thread. Nenhuma outra classe a usa. Em `draw`, a máscara é pega uma vez e desenhada na hora. O `release()` acima de 64
  acontece antes de criar a nova máscara.
- **Snapshot** (`HomeView.java:2389-2418`): `bitmap` é a única referência. Ele é usado só no UI thread e só no
  `Ui.LEGACY`.
- **Symbols** (`Symbols.java:86-96`): é estático e compartilhado em `:home` (Settings, QuickPanel, DreamView, e o
  `HomeApps.java:1264-1265` em outra thread). O tamanho que sai é reciclado dentro de `synchronized (PAINT)`. Só
  `drawLocked` lê `SIZED`, e no mesmo lock, desenhando na hora. Ninguém recebe um tamanho fora da classe. O PNG base
  (`CACHE`) nunca é reciclado (`s != b`). Para os passos intermediários vale a mesma guarda.
- **Display lists já gravadas:** no Android 8+, `Bitmap.recycle()` só larga a referência do wrapper Java. O RenderNode
  (10+) e a Picture do `Recording.Pic` (8 e 9, que grava via `SkiaCanvas`/`SkRecorder`) seguram o próprio ref ou uma
  cópia do pixel ref. Então reproduzir uma gravação antiga é seguro. Isto é raciocínio sobre o código do AOSP, sem
  teste: o testador deve confirmar num Android 8 a 11 (ver abaixo).
- **Concorrência:** `crispLogos`, `crispMade`, `shadows` e os Snapshots só são tocados no UI thread. Nenhum executor os
  preenche.
- **`destroy()`** (`HomeView.java:768`): depois de `pause()`. Como os mapas foram esvaziados, mesmo um desenho tardio da
  view antiga refaria os bitmaps em vez de usar os reciclados.
